# 评测数据与执行范围

## 第 24 天：第四周评测集

`week4_questions.jsonl` 为独立的新评测集，共 **30 题**：HR、财务、IT、产品、流程申请、无依据拒答各 5 题。知识问答涉及全部 12 份 `docs/sample_knowledge_base` 样例文档；输入中的姓名、部门和公司信息均为虚拟演示数据。文档路径和当前 SHA-256 保存在 `week4_corpus.json`，后续变更文档时需同时复核标注，不能只更新哈希。

这次交付是评测数据与人工标注，**尚未执行新场景效果评测**。第 25 天再适配执行脚本和指标，不把数据校验通过当作系统效果通过。

| 字段 | 含义与使用规则 |
| --- | --- |
| `id` / `category` / `question` | 稳定且唯一的编号、六类场景、单轮独立输入；category 不是路由标签 |
| `expected_route` | 与 `AgentRouteType` 枚举值一致；表示期望行为，不根据当前模型或规则输出反向修改答案 |
| `should_reject` | 是否必须因缺少所问事实而拒答；与路由独立，不将所有拒答题归为 irrelevant |
| `expected_source` | 预期证据文件的仓库相对路径；普通问答必填，流程提取和拒答为 null，不代表这两类必须没有检索结果 |
| `evidence_section` / `evidence_quote` | 普通问答的章节和可在原文找到的证据摘录；用于复核，不要求回答逐字引用，也不保证摘录覆盖完整答案 |
| `reference_answer` | 人工参考答案，基于当前样例文档；不参与模型输入，不要求逐字匹配 |
| `keyword_groups` | 外层为需要覆盖的事实组，内层为任选一个的等价表达；例如 `[ ["3 个工作日", "三个工作日"], ["HR 系统"] ]` 表示两个事实都要覆盖。组内用 OR，组间用 AND；后续脚本应记录每组命中以统计覆盖率 |
| `expected_fields` | 流程题的六字段参考 JSON；姓名、部门、权限和审批人核对原文，申请类型等允许等义表达，如“VPN权限”与“VPN 权限” |
| `expected_missing_fields` | 流程题所有 null 字段的集合；缺失值不能根据制度默认权限或审批角色补全 |
| `can_submit_after_extraction` | 仅依据当前后端必填项 application_type、applicant、department 判断是否具备提交条件；true 不代表已提交、获批或执行成功 |
| `forbidden_claims` | 拒答题的人工复核项；出现拒答句但又编造金额、IP 或凭据，仍应判失败，不能只依赖关键词 |
| `dify_comparable` | 可用于当前四文档 Dify 应用的共同问题子集，共 14 题；不含流程题或依赖未导入文档的问题 |

### 关键覆盖

- HR：年假提前量、试用期病假上限、远程办公审批、新员工资料补交、岗位试用期区别。
- 财务：报销时限、票据缺失、超过金额阈值后的复核人、不同城市住宿标准、供应商付款审批。
- IT：VPN 排错与锁定、Maintainer 审批角色、临时权限到期、源代码外传限制。
- 产品：支持格式、扫描件边界、需求冻结、灰度条件、反馈处理时限。
- 流程：完整 VPN/GitLab 申请、缺部门阻止提交、可选字段缺失、缺申请人及部门；只做路由和提取，不批量调用真实 n8n。
- 拒答：奖金金额、具体税号、VPN 公网 IP、年假现金折算、管理员凭据。既包括完全没有的事实，也包括文档命中却缺少关键细节的问题。

`it_03` 只咨询审批规则，期望 it_support；`process_01`～`process_05` 明确要求办理，期望 process_apply。`hr_03` 询问远程办公制度而非提交申请，期望 knowledge_qa。当前关键词兜底规则可能误判此类题，这些用例用于暴露问题，不保证现有代码全部通过。

### 第 25 天执行约定

1. 新执行器读取 `week4_corpus.json` 中的原始文档，用现有切块流程构建独立评测库，不沿用旧脚本的六个硬编码 chunk；运行前核对哈希。
2. 检索命中、答案引用命中、答案关键词覆盖分别统计。路径与返回的文件名需要映射，切块编号由实际入库结果确定，不把不稳定的 chunk 编号写成金标。命中来源不等于答案正确引用。
3. 普通问答、拒答、流程各用适用的指标与分母；流程题不因缺少 expected_source 计为拒答或检索失败。拒答不能只按是否检索到片段判断。
4. 单独统计流程意图识别：既检查 5 个正例，也检查其余 25 题是否被误判为申请，报告混淆情况。流程字段结果另行展示，不与意图识别混为一个分数。
5. 模拟路由/模型结果的单元测试只能证明脚本逻辑；实际系统结果需标明真实模型或规则模式，不把模拟输出写为真实准确率。不向真实 n8n 自动发送这 5 个申请。
6. 两版对比只使用 `dify_comparable=true` 的 14 题，并记录模型、Prompt、索引参数；Dify 未导入的另外 8 份文档不计为它的问答失败。

## 旧版评测保留

`questions.jsonl` 的 18 题与 `run_eval.py` 中的固定六个 chunk 配套。原命令仍为：

```powershell
.venv\Scripts\python.exe eval/run_eval.py
```

它只评估旧语料的检索及引用上下文，不调用模型生成答案、不执行流程，也不会读取新的第四周数据。旧报告不能作为本次 30 题的评测结果。两套语料的制度可能不同（例如发票复核角色），标注必须以各自绑定的语料为准，不能混用。
