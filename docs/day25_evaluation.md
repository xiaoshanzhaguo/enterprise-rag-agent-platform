# 第 25 天：新场景评测与实际基线

本次适配 [30 题评测集](../eval/week4_questions.jsonl)，保留旧版脚本，新增 [run_week4.py](../eval/run_week4.py) 与独立的 [指标模块](../eval/week4_metrics.py)。运行时间为 2026-10-26；只使用虚拟样例资料，没有向 n8n 提交申请。

## 运行方式

在项目根目录执行（使用项目现有 Python 依赖）：

```powershell
# 无模型调用：真实切块、SQLite 入库、规则路由和检索
.venv\Scripts\python.exe eval/run_week4.py --mode offline

# 真实模型：需根目录 .env 已配置 DEEPSEEK_API_KEY、BASE_URL、LLM_MODEL
.venv\Scripts\python.exe eval/run_week4.py --mode live
```

默认 top_k=3、keyword 检索，可用 `--top-k 1..5` 和 `--retrieval-mode vector` 修改。vector 模式仍允许现有关键词回退，报告逐题保留实际检索方式，不能仅凭启动参数声称结果全部来自向量检索。当前报告仅验证 keyword 模式，未执行向量基线。

每次运行使用唯一临时数据库和向量目录，强制隔离业务配置；原始文档先校验 SHA-256，再用生产切块和存储函数入库。live 直接消费 `run_agent_stream` 的真实 SSE 输出，保留独立会话，不复用对话历史；为避免额外标题模型调用，预设评测会话标题。模型请求超时 60 秒、禁用模型客户端自动重试；路由失败仍可能触发生产规则回退，报告表示整条实际服务链路效果，不是纯模型分类成绩。

默认输出 `eval/week4_offline_report.json/.md` 或 `eval/week4_live_report.json/.md`，也可指定 `--output 路径.json`。退出码 0 表示运行完成，不代表所有质量指标通过；运行错误会保留在报告并返回 1。初始化失败则不生成新报告，旧文件可能仍存在，应同时检查退出码与报告时间。评测不覆盖 HTTP、前端展示或真实审批执行。

## 指标定义

| 指标 | 分母与成功条件 |
| --- | --- |
| 检索命中 | 20 个有依据问答；期望文件进入实际召回结果。不要求 chunk 编号固定，也不证明召回片段充分支持答案 |
| 答案引用命中 | 同一 20 题；最终答案中出现期望文件的引用，且引用的 chunk 确实被召回。只把来源放进 Prompt 不算，编造 chunk 编号不算；不代表每句话都正确引用 |
| 答案关键词覆盖 | 20 题合计 50 个事实组；每组命中任一等价表达即覆盖，去除引用标记后检查答案正文，归一化空格、全半角和大小写。不代表完整语义正确性 |
| 无依据拒答 | 5 题逐条阅读复核；明确资料不足且没有编造所问事实。拒答标记单独保存为初筛信号，不能只凭固定句子判正确 |
| 流程意图识别 | 全部 30 题，5 个申请正例加 25 个非申请反例；报告 TP/FP/FN/TN，错误请求不计成功。另报六类路由完全匹配率，避免混淆两种指标 |

offline 不生成或伪造答案，因此引用、答案关键词、拒答指标均为 N/A。流程题的 null 来源不表示拒答，不参与检索指标。六字段另存逐字段严格匹配结果（忽略空格和大小写）；类型同义词尚需人工复核，不把它包装成语义提取准确率。

## 拒答复核与重算

先阅读 JSON 中 5 条拒答题的实际 `answer` 和对应召回片段，按金标及 `forbidden_claims` 给出结论。复核文件格式见 [本次复核记录](../eval/week4_refusal_review.json)，每条包含 `answer_sha256`、布尔值 `correct`、`reason`、`reviewer`。本次由 Codex 逐条阅读复核，不是用户人工签字或独立专家评审。

```powershell
.venv\Scripts\python.exe eval/run_week4.py --rescore eval/week4_live_report.json --refusal-review eval/week4_refusal_review.json
```

重算不请求模型；复核必须绑定实际答案的 SHA-256，答案变化后旧复核会被拒绝。完整匹配后复核内容一并写入报告，之后不传复核文件重算也会保留结论。评测集或语料清单变化后禁止用旧报告重算。首次 live 运行的拒答准确率待复核，不能把已复核部分的比率当作全部 5 题结果。

- `finance_01/02/03/05` 被分入 finance_process 后进入字段提取分支，返回申请 JSON 而非制度答案。这解释了 4 个引用失败，不是未召回正确文件；后续需区分财务制度查询与实际申请。
- `refusal_02` 同样返回字段 JSON，没有回答缺少具体税号依据；`refusal_01` 没有编造金额，但声称数字属于“尚未披露”的信息，文档无法支持该断言，按严格证据边界判失败。
- 其他拒答虽有不同措辞，明确说明资料缺少所问细节且未猜测事实，因此复核通过。固定拒答句匹配不能替代这一步。
- 部分 IT、产品问题被归为 knowledge_qa，但仍给出有据答案；六类路由不匹配不等于回答错误。`process_05` 将“VPN 账号”提取为“VPN 权限”，严格字段匹配提示这一差异，未擅自修改金标。

每题保存 `request_id`、路由、实际检索信息、答案、召回片段、阶段状态与耗时。此 Trace 目前属于评测报告，不等于业务系统已具备统一的持久化全链路追踪。下一轮应优先修复已定位的业务分支，再复跑并对比报告，之后接真实执行日志页面。
