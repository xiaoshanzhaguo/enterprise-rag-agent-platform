# 求职展示的渐进优化

目标是让面试官能运行项目、核对证据、看懂技术取舍。每轮只完成一个可验收目标，并用测试与实际演示说明效果。

| 顺序 | 小目标 | 验收依据 |
| --- | --- | --- |
| 本轮已完成 | 每条回答可核对路由、检索、耗时和追踪编号；修复旧历史恢复兼容性 | SSE 与 SQLite 摘要一致，刷新可恢复，跳过/拒答/失败状态明确 |
| 已完成第二轮 | 修复产品发布治理路由边界 | 原 30 题真实路由从 25/30 到 28/30，相似表达 5/8 到 8/8；对照报告保留 2 个未解决问题 |
| 已完成第三轮 | 明确企业数据与设备安全制度路由 | 原 30 题 28/30 到 29/30；新增安全回归 4/8 到 8/8，原产品样例不退步；IT 范围内实际检索通过 |
| 下一轮优先 | 从剩余路由问题与问答证据中确定一个改进目标 | 先核对业务分类边界，再用固定用例检查收益与回归，不以新增页面代替质量提升 |
| 后续 | 完善启动和演示的可复现性 | 新环境按文档启动，健康检查、错误提示与三条演示链路可复核；容器仍需单独完成真实验收 |
| 最后 | 对齐项目说明、演示材料与面试表达 | 所述能力均有代码、数据或演示证据；讲清模拟流程和当前边界 |

当前优先优化问答质量与运行稳定性。多会话、反馈和处理待办已经具备基础闭环，暂缓继续扩展管理页面。统一日志、权限、混合检索、重排等能力应在现有问题和测量结果支持时逐项引入。
