# PROD-03 客户反馈收集与需求分级流程

适用范围：产品、客服、销售、交付和客户成功团队。

## 反馈入口

客户反馈可以来自客服工单、销售拜访记录、客户成功周报、用户访谈和线上反馈表。所有反馈需要统一录入产品反馈池，不建议只保存在个人聊天记录中。

录入反馈时，需要填写客户名称、客户行业、反馈来源、问题描述、影响范围、期望结果、截图或录屏材料。

## 需求分级

产品团队按 P0、P1、P2、P3 四级处理需求和问题。

P0 表示核心功能不可用、数据错误或大面积客户受影响，需要当天响应并进入紧急处理。P1 表示重要客户或关键流程受影响，需要 3 个工作日内给出处理计划。P2 表示体验优化或中等影响问题，进入版本规划。P3 表示低频建议或长期优化，进入需求池观察。

## 评审节奏

产品经理每周三进行一次反馈池梳理，每两周组织一次需求评审。参与人包括产品、研发、测试、客服和销售代表。

需求进入版本计划前，需要明确业务价值、影响客户数量、实现成本、风险点和验收标准。

## 客户回复

客服和客户成功团队负责对外同步处理进展。P0 问题需要每 2 小时同步一次进展，P1 问题需要每天同步一次进展，普通需求可在评审后统一回复是否进入计划。

## 常见问题

Q：客户提出的需求是否一定要做？  
A：不一定。产品团队会结合客户价值、通用性、实现成本和战略方向综合判断。

Q：没有截图的反馈可以录入吗？  
A：可以录入，但需要尽量补充复现步骤、客户描述和影响范围。
