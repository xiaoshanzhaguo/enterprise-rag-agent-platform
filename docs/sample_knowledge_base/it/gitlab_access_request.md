# IT-02 GitLab 权限申请与代码仓库规范

适用范围：研发、测试、产品、运维和需要访问代码仓库的项目成员。

## 权限等级

GitLab 仓库权限分为 Guest、Reporter、Developer、Maintainer 和 Owner。普通研发成员默认申请 Developer 权限；测试和产品成员通常申请 Reporter 权限；Maintainer 权限仅授予项目技术负责人或模块负责人。

Owner 权限由平台管理员保留，原则上不对普通项目成员开放。

## 申请流程

申请人需要在 IT 服务台提交 GitLab 权限申请，填写项目名称、仓库地址、申请权限等级、申请原因和预计使用期限。直属主管需要先审批，涉及 Maintainer 权限时，还需要项目技术负责人审批。

IT 支持人员会在审批完成后的 1 个工作日内开通权限，并在工单中回复处理结果。

## 权限回收

员工离职、转岗或项目结束后，直属主管需要在 3 个工作日内发起权限回收申请。临时项目权限默认有效期为 90 天，到期后需要重新申请。

## 代码仓库规范

主分支 `main` 和发布分支 `release/*` 禁止直接 push。研发成员需要通过 Merge Request 合并代码。涉及生产配置、数据库脚本和权限变更的 MR，需要至少 1 名 Maintainer 审核。

## 常见问题

Q：为什么不能直接申请 Maintainer 权限？  
A：Maintainer 可以管理分支保护、合并请求和成员权限，权限较高，因此需要项目技术负责人额外审批。

Q：临时查看代码应该申请什么权限？  
A：只需要查看代码或下载代码时，申请 Reporter 权限即可。
