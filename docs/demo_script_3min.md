# 3 分钟演示脚本

目标：用知识问答、流程申请、无依据拒答三条链路展示当前项目。语料和人名均为虚拟演示数据，不把模拟工单说成实际审批或授权。

## 开场前准备（不计入 3 分钟）

1. 按 [部署说明](deployment.md) 启动，打开 React 主入口，确认后端健康及模型配置可用。
2. 在知识库管理中，将以下文档逐个上传并选对应分类：`hr/leave_policy.md`、`finance/reimbursement_policy.md`、`it/gitlab_access_request.md`、`it/vpn_troubleshooting.md`，路径均在 `docs/sample_knowledge_base` 下。确认页面显示已收录文档；首次索引和模型加载放在正式录屏前完成。
3. n8n 中已导入模板、配置 Header Auth、发布工作流；FastAPI 使用与其运行位置匹配的 URL。先演练一条新申请，核对执行记录与模拟回执。
4. 流程页若恢复了旧申请，先查询并核对，再新建另一份；不要为了录屏直接清掉未知结果的编号。提前收起包含密钥或控制台凭据的窗口。
5. 使用已跑过的检索模式；keyword 即可，不必为了演示改成尚未验证的向量配置。不要声称录屏中的检索一定使用向量。

## 00:00～00:15｜定位

展示工作台导航，口述：

> 这是面向企业内部资料的知识与流程助手。员工可以查制度、核对回答依据，也可以描述申请、修改字段并确认提交。后端保存申请状态，方便追溯和避免重复提交。

## 00:15～01:05｜知识问答

打开智能问答，选择企业默认知识库与 HR 分类，输入：

> 员工年假至少要提前几个工作日提交？

核对“至少提前 3 个工作日”“HR 系统”，展开或查看右侧引用，指向 `leave_policy.md` 的实际片段。不要预设 chunk 编号。

口述：

> 系统先判断问题和改写检索词，再调用知识库 Tool，把命中的片段交给模型生成答案。引用让用户能够回到原文核对，展示的检索方式是本次实际使用的方式。

若需替换问题，可用“日常费用发生后，报销申请需要在多久内提交？”并切到财务分类，预期为费用发生后 15 个工作日内。只问一题，避免超时。

## 01:05～02:05｜流程申请

切到流程助手，输入：

> 我是研发部张三，申请 VPN 只读权限，用于远程办公，审批人为李经理。

依次操作：提取字段 → 核对六项 → 将部门修改为“平台研发部” → 确认提交。

展示“流程已触发 / 已记录”、申请编号与 `SIM-` 开头的工单编号。点击“在执行日志中查看此申请”，打开详情，核对编号和修改后的部门。

口述：

> 提取不会自动执行。用户确认后，后端先保存申请，再请求 n8n；校验回执并保存成功后才展示成功。同一编号不能重复提交。这里是模拟表格、通知和工单，不会真实发通知或开权限。

## 02:05～02:35｜无依据拒答

回到智能问答，将检索分类切回全部，输入：

> 星辰科技2027年度董事长奖金的准确金额是多少？

展示明确缺少资料的回答，确认没有编造金额，也没有宣称公司未披露该信息。

口述：

> 没有找到依据，不等于事实不存在。即使命中其他制度片段，也不能用常识补出公司内部数字。

## 02:35～03:00｜验证与边界

打开评测结果页，说明这是已保存的验收快照：30 题覆盖六类场景，区分检索命中、答案引用、关键词覆盖、拒答与流程意图。指出六类路由匹配为 83.3%，不把全部指标说成满分。

口述：

> 项目有独立评测库与逐题报告，能定位“检索到了但没有正确回答”的问题。目前仍是本机演示，登录隔离、完整业务 Trace 和真实审批对接是后续优化方向。Dify 版本用于简化问答对照，没有替换这套代码链路。

## 异常时怎么演示

- 模型慢：保留加载状态，不反复点击发送；无法在时限内恢复时，说明当前请求未完成，另展示已保存报告并明确它不是这次实时回答。
- 流程超时：展示超时/待核对提示与编号，去执行记录核对；不换编号重新提交，不把 unknown/timeout 说成成功。
- 资料缺失：展示空状态，补上传资料后重新提问；不用准备好的文字冒充模型实时输出。

这是建议节奏；实际耗时受模型和网络影响。正式录屏前先完整演练一次，保留成功与异常处理的真实边界。
